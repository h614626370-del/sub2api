# BPS 403 会话屏蔽与请求明文留存

在管理后台「系统设置 → 功能开关」的「BPS 403 会话屏蔽与请求留存」中配置。打开「BPS 403 会话自动屏蔽」及「自动保存 403 请求的完整明文」，设置屏蔽时长后保存。两个开关互相独立，默认关闭。屏蔽时长默认 3600 秒，可设为 1–604800 秒。

## 触发与影响范围

- 实际发出的上游请求路径必须精确等于 `/basispoints/api/responses`，且上游 HTTP 状态为 403。主请求、压缩和修复重试适用同一规则。
- 原生 Codex 接口、附件接口、本地返回的 403，以及上游 401、429、200 均不触发。403 的具体错误代码不影响触发，例如 `basispoints_model_access_changed` 也会触发。
- 沿用 cyber 功能的明确会话识别规则，按 API Key 与带类型的 `thread_id` / `session_id` 隔离。两种屏蔽独立存储、独立开关。
- 后续同会话请求在账号选择前返回 `session_blocked_by_bps403`，适用于 Responses、Chat Completions、Messages 兼容入口和 WebSocket 入站会话检查。当前失败请求沿用原有响应和故障处理流程。
- 无法可靠识别会话时，仅按开关留存失败请求，不扩大屏蔽到整个用户、API Key、账号或 IP。
- 新会话不受旧会话屏蔽影响；TTL 到期后自动解除，关闭会话屏蔽开关立即停止拦截。开关不主动删除 Redis 记录，重新开启时尚未过期的记录继续生效。
- 保留既有 BPS 账号禁用或移组逻辑；这是额外的会话保护，不替代账号处理。

## 明文查看与导出

开启「自动保存 403 请求的完整明文」后，每个触发请求会在管理员「请求采集」页面自动生成一条「BPS 403 自动留存」任务，无需创建手动任务，也无需打开普通「启用请求采集」开关。同一个入站请求的多次修复最多自动留存首次实际 403。

从侧栏进入「请求采集」，或点击设置中的「查看 BPS 403 请求记录」（路径 `/admin/request-captures`）。点击「BPS 403 自动留存」任务，再点击 Request ID，即可切换「客户端请求」「上游请求」查看正文，使用「下一段」继续查看长正文，或点击「导出」保存压缩包。

记录包含两份请求正文：

1. `client_request`：服务收到并解压后的原始 JSON，包括本次提交的消息、历史与工具结果。
2. `upstream_request`：实际发往 BPS、得到该次 403 的转换后 JSON，包括网关补入的指令。

正文不按普通错误日志长度截断。页面按段预览，可导出任务 `.tar.gz` 压缩包查看全部已保存内容。索引记录包含状态、请求 ID、上游请求 ID、账号、API Key ID 和会话哈希；数据库索引及常规日志不存正文。

“全部明文”指本次请求实际携带的明文。系统不能补齐客户端未提交的历史，也不能解密上游 opaque/encrypted 内容。沿用现有留存过滤：认证凭据脱敏，二进制图片、音频、文件只留摘要。

## 容量与权限

- 沿用请求采集的磁盘配额和保留天数，默认 1024 MiB、7 天，配置位于同一「功能开关」页的「请求采集」卡片。
- 沿用单记录 128 MiB 上限和内存/队列容量限制；达到限制时记录标记为不完整，或增加跳过计数，不承诺容量不足时完整落盘。
- 文件使用现有私有目录与管理员权限接口。任何查看和导出仍需管理员身份；普通用户无法访问。
- 留存故障不会改变原有 403 响应，也不会撤销已写入的会话屏蔽。

配置键：`bps403_session_block_enabled`、`bps403_session_block_ttl_seconds`、`bps403_capture_enabled`。
