# 生图主控

将 `h614626370-del/responses-image-bridge` 的请求适配和监控功能集成到 Sub2API。
参考本地源项目提交 `f285450`，以 Go 实现站内调用，不启动 Node 服务、不新增监听端口。

## 入口与启用

- 管理员侧栏：**我的运维 > 生图主控**，位于“智能运维”之后、“插件”之前。
- 首次默认关闭。在“主控设置”顶部启用并保存后，对当前实例的新请求生效。
- 不需要上游地址、管理员 Key 或独立管理口令；使用现有 Sub2API 管理登录和权限。
- 客户端仍使用本站地址和自己的 API Key。管理员 Key 不能用于替代用户生图 Key。
- 未移植账号诊断、账号查询、诊断用量关联及其配置、接口和页面。
  不删除 Sub2API 原本的账号管理、用量及运维功能。

## 接入范围

开启后，仅接管 OpenAI / Composite 分组中包含原生
`tools[].type = "image_generation"` 的 POST 请求：

- `/v1/responses`
- `/responses`
- `/backend-api/codex/responses`

普通对话及没有生图工具的请求不变。原有鉴权、余额/订阅校验、模型白名单、
分组流式限制和生图权限仍生效。改写后的目标模型也需要通过模型白名单；
账号选择、上游访问、审核、并发、扣费和用量记录继续由原网关完成。
不会重复鉴权，也不在适配层重复记账。

直接调用图片接口、普通对话及 WebSocket 不受本功能改写，不新增静态模型列表。此功能不扩展账号本身支持的模型，
不改变账号的上游地址，也不能绕过原有分组、模型或生图限制。

### 同步图片中转

总开关统一控制文生图和图生图，不再提供“Responses 主控模型”或“图生图直连”设置：

- 无原图：同步调用本站 `/v1/images/generations`，JSON 中明确 `stream=false`。
- 有原图：同步调用本站 `/v1/images/edits`，使用非流式 multipart 请求。
- 图片模型必须来自唯一的 `image_generation` 工具中的 `model`（例如 `gpt-image-2`）。
  缺失或非法直接报错，不使用顶层 `model` 兜底，也不指定默认图片模型。
  顶层 `model` 仅用于原入口准入、Responses 响应兼容和日志，不会调用它。

支持字符串 `input` 或单条用户消息；消息内容可以是字符串，或 `input_text` /
`input_image` 列表。`instructions` 与用户文本合并为图片提示词，保留文本内容。
支持 `size`、`quality`、`background`、`output_format`、`output_compression`、
`moderation`、`input_fidelity`、`style` 和 `input_image_mask`。
选项的实际可用性仍由原网关和账号决定。最多 8 张原图，每次只生成 1 张图片。

多工具、多轮、历史引用（`previous_response_id`、`conversation`、消息 ID）、
模板提示词、空用户提示词、未知内容和无法转换的参数明确报错。
例如 `reasoning`、`text` 输出约束、`stream_options`、`store=true` 不支持；
`store=false` 和 `background=false` 可使用。`tool_choice` 仅接受 `auto`、
`required` 或 `{"type":"image_generation"}`。
`action=edit` 必须有原图，`action=generate` 不能同时携带原图；
遮罩与 `input_fidelity` 必须有原图。不忽略上下文后继续生图。

对流式客户端，等待期间发送 SSE 注释心跳，完整图片返回后发送 Responses 事件；
对非流式客户端返回 Responses JSON。适配层生成 Responses ID 和输出项 ID，
保留图片结果及图片接口的 usage。`partial_images` 允许 0 至 3 的整数，
但不向同步图片接口传递，也不提供局部图片或伪造进度。
同一图片出现在输出项完成事件和最终快照中，客户端应按输出项 ID 去重。

### 原图与遮罩

支持 Base64 PNG/JPEG/WebP 和公开 HTTPS 图片地址；单张最多 50 MiB、
4000 万像素。下载会校验并固定公网目标 IP，拒绝内网、回环、保留地址和不安全跳转，
不携带用户 Key，不使用进程代理。任一下载失败会取消其余下载。
与独立项目的 sharp/WebP 实现不同，站内版使用 Go 将远程图片无损规范化为 PNG，
不需要额外原生图片运行库；内嵌 Base64 图片保留原格式。

`file_id` 不支持。原图和遮罩仅使用 `image_url`，输入图的 `detail` 仅接受
省略或 `auto`，不支持需要主控解释的细节参数。

### 禁止主控回退

转换后的请求携带内部“仅图片直连”标记。OAuth 账号映射后的图片模型不支持直连，
或直连接口返回 404/405 时，不会改调 Responses 主控，而是沿用原网关的有界账号切换。
无法找到可直连账号时返回 `image_direct_required`。API Key 账号仍走图片接口。
标记仅在本功能接管的请求上生效；关闭功能或其他调用保留原有回退行为。
第三方上游服务内部如何实现图片接口不在本站控制范围内，不能保证其内部不使用主控。

跨节点使用原签名路由票据携带直连策略，在签名与重放校验后恢复。
策略使用独立签名域，移除或注入策略会导致验证失败；不支持策略的旧节点也会
拒绝该签名，不会静默忽略后继续生图。客户端自行添加的未签名策略头不生效。
混合版本集群应先升级接收节点，再开启入口功能。

## 运行控制

| 设置 | 默认值 |
| --- | --- |
| 启用 | 关闭 |
| 总超时 | 900 秒，包含准备原图和网关处理（含网关内等待） |
| 心跳间隔 | 5 秒，仅适用于流式请求 |
| 请求体上限 | 128 MiB |
| 结果上限 | 64 MiB |
| 附加 `[DONE]` | 关闭 |
| 完整原始请求日志 | 关闭 |

全站及反向代理的请求大小限制仍优先约束入口，不能靠调高这里的值绕过。
主控不设置独立并发上限、不建立等待队列，也没有暂停/恢复接口；
并发和排队统一由 Sub2API 原有分组及网关策略承担。旧主控配置中的
`max_concurrent`、`max_queue`、`control_model`、`direct_edits` 等字段不再生效，
重新保存设置后移除；原有 `enabled` 值保留。无需数据库迁移。
图片解码和磁盘写入等本地同步操作不能保证立即响应取消。

支持取消单条请求、筛选、分页、时间线、删除完成记录和导出。
监控中的“执行中”包括准备原图、在网关中等待、处理和结果交付，不单独展示主控排队数。
取消和超时会传递给原网关，但不能保证上游已经开始的生图立即停止或不产生费用。
关闭主控后新请求恢复原来的网关行为，已经接管的请求继续按原配置完成。

适配层不主动重试、不增加计费；原网关的有界重试、账号切换和计费仍负责实际生成。
本功能接管的请求仅禁止回退主控，不能据此承诺每个请求永远只发生一次上游调用。

## 日志与安全

配置和日志保存在当前实例的 `DATA_DIR/image-master/` 下，
不新增数据库表，不迁移独立服务已有配置或日志：

- `config.json`：不含上游地址或管理凭据。
- `requests.json`：请求元数据，不保存提示词、图片内容和完整用户 Key。
- `raw/*.json`：仅显式开启完整原始请求日志后保存，包含请求头和原始 JSON 正文，
  可能包含用户 Key、提示词和图片。启用前页面要求确认。

元数据通常最多 10,000 条；如果全部为执行中记录则暂时保留，完成后再收敛，
不会因日志条数限制拒绝生图。原始请求文件合计最多 256 MiB，达到上限不再保存新原始请求，
生图继续运行并显示存储异常。记录按 12 小时保留，运行中的记录不会中途删除，
每分钟清理一次。只将已完成的元数据持久化；进程异常退出时在途记录可能丢失，
遗留原始文件在下次启动清理。文件使用原子替换，创建权限为目录 0700、文件 0600
（Windows 上还应使用宿主机 ACL 保护数据目录）。

查看原始记录复用本站管理员二次验证策略，并纳入敏感读取审计。
导出只包含元数据，不包含原始正文和凭据。完整日志不得提交 Git，
备份数据目录时需按敏感数据保护。
监控区分“文生图直连”和“图生图直连”，详情保留原请求模型与提取的图片模型；
账号映射后的上游模型继续由网关运维日志记录。旧 Responses 记录仍可查看和筛选。

**主控配置、统计和日志均按当前进程/实例独立管理，不是集群全局配置。**
多副本部署需要逐实例配置并定向查看；多个进程不能共同写同一个
`image-master` 目录。共享管理入口若随机分配实例，页面可能看到不同设置和记录。
需要统一控制的部署应在有固定持久目录的单一入口实例启用。

## 验证边界

本地测试使用模拟网关和合成图片，覆盖请求转换、SSE 心跳、取消、网关限流、存储、
权限和界面操作。未调用真实收费生图接口，未验收真实客户端解析器、
OAuth/API Key 账号的实际图片能力或多实例部署。发布及部署前仍需在授权范围内联调。

回归测试覆盖同步请求转换、原图与遮罩、非法输入、响应和 usage、心跳与取消、
旧配置、权限和限流、直连接口 404/405、账号模型映射及账号切换，
并验证跨节点签名、防篡改与旧节点拒绝。真实收费生图、完整后端测试集、
Go 竞态检测和实际多节点部署仍需另行授权验收。

2026-10-08 本地验证通过：`imagemaster`、网关路由、`serverless` 三个包的完整测试，
图片直连服务与处理器的定向回归；前端 5 个文件共 65 项测试、类型检查、
相关文件 ESLint、前端生产构建及 Windows 嵌入前端的后端构建。
浏览器使用模拟接口核对设置保存、两种直连与历史记录、模型详情、
桌面和 390/320 像素手机布局及暗色模式。未启动真实后台服务，未连接服务器。

## 旁路对照（2026-10-09，本地新增）

入口：**我的运维 → 生图主控 → 旁路对照**。默认关闭；开启后复制所有符合条件的请求。
主控接管可以继续关闭。旁路开启时，上述三个 Responses HTTP 入口始终保留原业务路径；
即使两个开关同时打开，原请求也不会被生图主控接管。关闭旁路只停止新副本，已开始的测试继续完成。

### 配置与执行

1. 准备独立 OpenAI 分组，允许图片生成，关闭“仅流式”，账号只开放目标图片模型。
2. 为专用测试用户创建该分组的 API Key，在页面选择分组并填写 **Key ID**，不填写密钥正文。
3. 开启并保存。并发、排队和限流由测试分组及现有网关处理，旁路不额外设置抽样或并发门槛。

保存时校验 Key 状态、分组匹配、生图权限和仅流式限制；执行时再次鉴权。
原用户与测试用户相同、原分组与测试分组相同，或 Key 已换组的副本会被拒绝。
测试请求从回环地址进入站内独立路由，测试 Key 的 IP 规则需要允许该地址。
原用户仅承担原请求的正常费用；副本用测试用户的余额/订阅和 Key 额度正常结算，
相应使用记录可按测试用户或 Key 筛选。上游实际费用仍由所选账号承担。

识别条件为 `tools[].type=image_generation`；副本复用本页既有 `Prepare` / `encode`
转换与“仅图片直连”策略，无原图走 generations，有原图走 edits。提示词、支持的图片选项、
原图及遮罩保持现有转换语义。不调用主控模型，不在失败后退回主控。
第三方图片上游内部如何实现仍由上游决定。

复制范围与现有主控支持范围相同：单条自包含用户输入、唯一图片工具且有明确 `gpt-image-*`
模型。多轮隐藏上下文、缺少图片模型、额外工具、`reasoning` 等不支持参数只会使**副本**标记为
“无法转换”，不阻断、删除参数或改写原请求。直接 Images API、普通文本请求、WebSocket 不复制。

旁路独立路由重新鉴权并执行目标模型白名单、分组限制、账号调度、审核、并发和原计费。
不继承原请求的 Gin 状态、Cookie、认证头、用户配额或取消上下文；客户端断开不会主动取消副本。
副本只有内部调用，不能通过 HTTP 请求头触发，不经过旁路入口而形成递归。

### 资源与统计

- 副本请求体最多 16 MiB；超限原请求仍照常走原有大小校验，页面累计超大请求跳过次数。
  该次数是在识别完整 JSON 前计算，包含超大的非图片 Responses 请求。
- 所有符合条件的请求均进入独立测试路由；旁路不抽样，不因本地并发数量跳过。
  测试分组、测试 Key/用户及原网关的并发、排队和限流规则正常生效；原请求不等待副本。
- 超时、编码大小与测试响应上限沿用主控设置。原响应只保留最多 64 MiB 的内存观测副本，
  超出后停止观测，用户写出继续，结果标为未知。
- 原 JSON / SSE 必须存在已完成、非空的 `image_generation_call` 才记为收到图片；
  支持 `response.output_item.done` 加终态完成事件。仅 HTTP 200、仅 `[DONE]` 不算成功。
  完成但无图、流内错误、断连和未知分别记录。
- 成功率两列使用同一批两侧均有明确结果且转换已尝试的配对作为分母。
  无法转换、未知和执行中排除；成功中位耗时分别来自该配对集合中各侧成功的请求。
  指标按当前保留记录计算，不因列表搜索/筛选改变，不衡量图片质量。
- 记录源用户、源分组、目标分组与 Key ID、模型、耗时、图片数、HTTP 状态及固定错误码。
  新增旁路存储不保存提示词、图片、密钥或上游响应正文；不改变原有全站采集设置。
- 每实例已结束记录最多保留 2,000 条 / 12 小时，执行中记录另计；记录容量不阻止新副本进入网关。`image-master/shadow.json` 使用原子写入、0600 权限，
  每分钟及完成时持久化；重启发现未完成记录标记为未知。超大请求跳过计数仅统计本次进程。
- 可查看逐条两侧结果，按差异、失败、无法转换和模型/请求 ID 筛选，分页并导出元数据。

### 本地验收范围
