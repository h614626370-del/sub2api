# Sub2API v2.9.4：迁移至 ranxi2001 代码体系

## 本次变更

- 在原 `h614626370-del/sub2api` 仓库发布一次性过渡版本。
- 前后端、部署及发布代码整体采用 `ranxi2001/sub2api` 正式标签 `v2.9.4`，固定提交 `7dd10bfe4b635f226f0ddfa52cc65797697272d8`。
- 移除原定制版的专属业务实现，不再沿用原四段版本号；保留 Git 历史与旧版本标签。
- 加入一次性数据库迁移和回归测试，覆盖定制版 `v0.2.7.8`、`v0.2.10.1` 的迁移及原版迁移器接续。

## 重要：启动前备份

**首次启动会自动迁移数据库。请先完整备份数据库、部署配置和持久化密钥。**

确认属于旧定制版的数据库后，过渡脚本会永久删除以下废弃数据：

- `openai_codex_ticket_audits`：旧打票审计。
- `codex_ticket_attempts` 及其分区、独立序列：旧打票尝试历史。
- `codex_ticket_invalidations`：旧票据失效历史及其中保存的票据材料。

过渡脚本不删除用户、余额、冻结余额、原 API Key、订阅、订单、历史用量、普通账号凭据、代理或分组关系。目标项目自身的增量迁移照常执行。

旧 Astra/Sol 特殊账号池路由、请求时区及相关专属配置被退役。迁移后需要检查原 API Key 所属分组是否具备可用账号和模型权限；脚本不会自动扩大分组授权。

旧打票总开关会一次性关闭，并清除旧票据材料。需要使用新版打票时，请重新检查配置后手动启用。目标项目的 Excel / BPS 功能沿用其自身设置，不把旧 BPS 选项强行转换成已启用状态。

存在遗留独立 `openai_bps` 账号或分组时，迁移会停止，等待单独的数据转换方案，不直接删除相关业务数据。存在未知表依赖时同样停止，不使用 `CASCADE` 强制删除。

## 后续使用原版

- 应用内更新来源采用目标项目原有的 `ranxi2001/sub2api`。
- 本过渡版镜像仍由本仓库发布：`ghcr.io/h614626370-del/sub2api:2.9.4`。
- Docker 部署以后改用原版，需要显式切换镜像仓库；仅修改旧仓库下的标签并不等于切换至原版。
- 回退旧定制程序需要恢复迁移前数据库和对应配置，不能只换回旧镜像。

发布不包含正式或测试服务器部署。完整迁移范围、限制及验收步骤见 [过渡说明](v2.9.4-transition.md)。
