# v2.9.4: one-time transition to ranxi2001/sub2api

## Provenance and scope

- Previous fork: h614626370-del/sub2api v0.2.10.1, commit
  `cb0f990b23d1571582b7c71358e4231df9e66bbc`.
- Application source: ranxi2001/sub2api **released tag v2.9.4**, commit
  `7dd10bfe4b635f226f0ddfa52cc65797697272d8`, not its later production HEAD.
- The application, frontend, packaging and upstream migrations are replaced by
  that exact source. No old private-updater, routing, timezone or ticketing
  implementation is carried forward. The owner's requested version is 2.9.4;
  the former four-component custom-version convention ends with this release.
- Repository history and previous tags are retained. Artifacts are published
  under h614626370-del/sub2api; publishing does not deploy any server.

## Database changes and irreversible cleanup

**Back up the database, configuration and persistent encryption keys before
starting this version.** Startup runs migrations automatically. Binary-only
rollback is not a supported recovery procedure after the transition.

The new `260z_h614626370_transition.sql` runs only on databases carrying known
legacy-fork migration records. It does nothing to a fresh database or an existing
unmodified ranxi2001 installation. The normal migration ledger prevents repeats.

The bridge permanently drops ONLY these retired custom tables:

- `openai_codex_ticket_audits` (normally already retired by v0.2.10.1);
- `codex_ticket_attempts`, its partitions and its standalone ID sequence;
- `codex_ticket_invalidations`, including historical ticket/cookie material.

No `CASCADE` is used: unexpected dependencies abort the bridge transaction.
Ticket audit history is deliberately not preserved by this cleanup. User usage
history is a different dataset and is not deleted.

Users, balances, frozen balances, API keys, subscriptions, orders, usage logs,
account credentials, proxies, group memberships and pricing are not deleted or
renumbered by the bridge. The upstream migrations still apply their own documented
schema changes (including pricing JSON normalization where not already applied).
Historical migration records/checksums are not edited. Superseded custom migration
files are archived outside the executable migration glob for audit and regression
tests; they are not replayed on new upstream installations.

The bridge removes the old Astra/Sol routing and account-request-timezone settings,
obsolete ticket configuration/material and old `openai_bps_*` account extras. It
disables ticket harvesting and fail-closed ticket gating once, so an old enabled
flag cannot silently start the new implementation. Configure upstream ticketing
again explicitly after validation. Unrelated account extras and all credentials
are preserved, including upstream `openai_excel_bps_*` settings.

If experimental standalone `openai_bps` account/group rows still exist, migration
stops with an error instead of deleting their subscriptions or usage history.
Such databases need a separately reviewed conversion. The retired destructive
`248_remove_builtin_bps.sql` is NOT replayed by this release.

## Operational acceptance

1. Use an isolated backup copy; never run old and new applications concurrently
   against the same writable database. Disable outgoing jobs during rehearsal.
2. Verify users, balances, subscriptions, original API keys, payments and usage.
3. The old Astra/Sol account-pool override no longer exists. Verify each original
   key's group has usable accounts/model permissions without that override. The
   migration intentionally does not grant new memberships or widen permissions.
4. Preserve existing JWT/TOTP/encryption configuration and persistent data. The
   upstream credential-operations file key, if subsequently enabled, must also be
   included in backups. Do not regenerate keys to work around decryption errors.
5. Verify with an unmodified ranxi2001 v2.9.4 binary before proceeding to its later
   releases. Extra historical migration ledger rows are ignored by that runner.
6. The application updater now follows **ranxi2001/sub2api**. Docker deployments
   must explicitly change their image repository to `ghcr.io/ranxi2001/sub2api`
   when leaving this one-time release; a tag change under the old owner is not
   an upstream switch. Same-version switching is explicit, not an update alert.

## Local verification (2026-09-30)

- The target GitHub release is published and is not a draft or prerelease.
- Application source and all 314 upstream SQL migrations match the pinned tag.
  Additions are limited to this bridge, historical fixtures, tests and release notes.
- Migration package unit tests passed.
- Real PostgreSQL 18 isolated tests passed for v0.2.7.8, v0.2.10.1 and an existing
  unmodified upstream schema. Snapshots of users, keys, subscriptions, orders,
  usage, credentials, proxies and memberships match before and after migration.
- Historical ledger checksums are preserved. Restart/manual replay preserves an
  administrator's subsequent ticketing choice. The original upstream migration
  set can take over successfully without this bridge file.
- Unknown table dependencies and leftover standalone BPS business records are
  rejected instead of destructively forced through.
- Frontend production build and 51 critical suites / 847 tests passed.
- Twelve release-helper tests passed on Linux. Linux amd64 backend build with
  embedded frontend passed; its version output is 2.9.4.

These are synthetic-data database and code/build regressions, not acceptance of
a production backup, real account permissions, live payments, or a deployed
unmodified upstream binary. No remote server was connected to or changed.
