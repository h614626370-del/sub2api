# 首页管理

进入「我的运维 → 首页管理」。每个实例只维护一份首页，不提供模板或单独的发布步骤。

- 在「首页文件」一次选择首页 HTML 和资源。入口使用不超过 1 MiB 的 UTF-8 `index.html` 或 `home.html`，两个文件都选时使用 `index.html`。
- 勾选「启用独立首页」，填写公开主域名（例如 `https://example.com`），保存后生效。已有首页升级后继续使用，可以单独替换入口文件或资源。
- 启用后，`/` 直接返回保存的 HTML，`/home` 和 `/home/` 以 `301` 跳转到 `/` 并保留查询参数。
- SEO 标题、描述、`canonical`、Open Graph 和 JSON-LD 直接写在 HTML 内，不重复配置。编辑页提示常见 SEO 问题，不改写源文件。
- `/robots.txt` 由后端生成；启用时声明 `/sitemap.xml`，后者仅收录配置主域名的首页。教程未加入本站点地图。
- 保存会保留上一版完整配置（开关、主域名、HTML）。恢复立即生效，并把刚换下的版本保留为上一版。并发编辑发生冲突时不会覆盖新版本。
- 关闭独立首页并保存后，继续使用原有首页（含系统设置中的旧 `home_content`）。已上传的文件会保留。仅后台模式不对外提供首页。

## 首页资源

同批上传的资源可以用同目录相对路径，例如 `<img src="./hero.jpg" alt="">`。路径和文件名区分大小写。也可以使用 `/homepage-assets/hero.jpg`，在资源名与应用文件冲突时用此路径。资源与 HTML 一起保存和恢复上一版，同名上传会替换对应文件。

- 支持 JPG、PNG、WebP、GIF、CSS 和 WOFF2。最多 32 个文件，单个不超过 2 MiB，合计不超过 8 MiB。
- 资源随 PostgreSQL 备份保存。独立首页启用时，当前版资源允许访客访问。
- 如果保存较大的资源时反向代理返回 `413`，请检查代理的请求体大小限制。保存请求还包含 Base64 编码和 HTML。

首页允许 HTML/CSS、普通链接以及符合页面策略的图片和字体。自定义 JavaScript、表单提交和嵌入均被禁用，禁止 `meta refresh`。不要在首页 HTML 放置密钥。首页配置和上一版随 PostgreSQL 备份保存。

在 `<head>` 中加入 `<meta name="sub2api-redirect-signed-in" content="true">` 后，有本机登录记录的访客会通过应用的登录路由进入对应控制台。首页管理的「打开首页」链接使用 `/?landing=1`，供已登录的管理员查看公开页面。

## 从 Guide 切换

1. 迁移 HTML 和它引用的静态资源，核对链接与规范地址。仍依赖 Guide 的 CSS、图片、字体及动态功能不会自动迁移。
2. 先在 Sub2API 启用并验收，再将反代的 `/`、`/robots.txt`、`/sitemap.xml` 交给 Sub2API。若已有 `/home` 跳转可保留，确保没有循环和缓存旧首页；旧 `/site-home/` 资源不要在替换前移除。
3. 等剩余 Guide 页面和直接链接完成迁移后，再下线 Guide。此功能不操作原 Guide 服务。
