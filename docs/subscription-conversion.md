# 订阅转余额

管理员入口：**我的运维 → 订阅转余额**。仅管理员可操作，不再向用户开放。
同一页面提供转换开关、用户搜索、订阅预估、确认转换和该用户最近 100 条转换记录。
开关默认关闭；关闭时仍可查询预估及记录，但无法提交转换。
用户菜单、页面路由以及旧的用户转换接口均已移除；公开设置中的旧功能标记固定返回 false。
管理员通过邮箱或用户名搜索目标用户，确认弹窗明确显示到账账户；到账的是目标用户余额，
不是管理员余额。订单审计以 `admin:<管理员ID>` 记录实际操作人。

## 当前开发状态

当前实现已完成，尚未发布、部署或开启真实用户转换。
管理员配置、用户预估与确认、原子到账和撤销已通过定向检查。
管理员确认后，**在同一事务内立即撤销订阅并增加用户余额**。
不检查进行中请求、后台扣费任务或失败结算记录，不排队、不等待，
也不按晚到用量补扣转换余额。请求认证不再登记转换租约，旧租约记录不影响转换。
转换不取消或改道请求，不自动切换 API Key 分组；请求继续按现有规则处理，
失去订阅权益后可能报错。管理员自行通知用户切换 Key 分组。

## 代码边界

转换逻辑集中在 `backend/internal/service/subscription_conversion_service.go`，
由独立的 `SubscriptionConversionService` 负责；原管理员接口通过薄入口调用，
跟主程序一起编译和部署，不需要新增服务、容器或配置。
请求认证、后台计费和视频任务不再维护转换专用租约。
历史迁移和租约表保留以兼容已有数据库，但不再参与转换判断。

现有撤销订阅和修改余额方法会各自执行写入与缓存更新；普通增加余额还会累计充值金额。
转换因此在自己的同一数据库事务中完成撤销和余额增加，提交后复用缓存失效逻辑，
避免撤销成功但到账失败，也避免把转换金额计为新的充值。

## 计算规则

```
转换余额 = 购买售价 × (剩余时间比例 × 50% + 剩余额度比例 × 50%)
剩余时间比例 = 剩余秒数 / 购买总秒数
总额度 = 月额度 × 购买天数 / 30
剩余额度比例 = max(总额度 - 订阅期间累计用量, 0) / 总额度
```

比例限定为 0–1；金额使用十进制定点计算，最终向下保留六位小数。
例如售价 30，剩余时间 50%、剩余额度 80%，到账 19.50。
仅支持月额度大于零、未配置日／周额度的分组。30 天为一个额度月；
续费累计购买天数，60 天按两个月额度计算。剩余时间精确到秒。

售价读取当前有效期内、已完成的支付订单 `amount`（购买时的套餐售价），
不读取套餐当前价格，不含支付手续费。沿用余额 USD 计价单位，不把上游网关
扣款金额 `pay_amount` 或展示币种标签当作另一份余额再换算。

## 来源与额度校验

- 管理员分配的订阅不允许转换；改为管理员操作不放宽购买来源和结算校验。
- 交叉核验 `assigned_by`、支付订单备注、订单所有者、分组、支付发放审计与完成状态。
- 购买天数必须与当前有效期吻合。备注含赠送／兑换码、手动调整期限、订单缺失、
  退款或来源不明时展示不可转换原因，避免把无偿权益折算成余额。
- 同一订阅记录可能保留上一个到期周期的订单；仅当前周期的购买参与折算。
- 迁移 `269_subscription_conversions.sql` 从当前周期的订阅使用日志初始化累计用量。
  若检测到该周期内执行过日志清理，或日志汇总小于现有周期计数，则标记历史不完整，
  不开放转换。迁移前通过数据库外部操作删除的历史数据无法自动重建，应先核实数据完整性。
- 新增数据库计数由订阅用量更新触发；日／周／月窗口重置不清空累计值，
  到期后开始新的有效期才重置。之后清理使用日志不影响累计值。

## 确认与记录

管理员选择目标用户后查看有效订阅、预计到账、订单号与计算明细；核对到账账户，
勾选了解撤销和退款限制后提交。切换目标用户会清除旧预估，确认期间禁止切换账户。
服务器重新计算金额；时间流逝和新增已记账用量可能让到账低于预估。
进行中请求、待结算任务及失败结算均不阻止预估或确认转换。
期限、价格或月额度变化时，旧确认失效，必须刷新后重试。

余额增加、转换记录、余额变更记录、订阅撤销、订单状态与订单审计
在同一数据库事务内完成。用户与订阅行锁串行化重复提交，
转换记录以订阅 ID 为唯一键；重试返回原收据，不重复加款。
事务失败时全部回滚。提交后刷新订阅、余额及 API Key 认证缓存。

已转换订阅保留撤销记录，禁止恢复；关联订单标记为 `CONVERTED`（已转余额），
不能再退款或重新发放权益。原购买金额继续计入支付统计和每日支付限额。
转换本身不触发充值返利。管理员按用户查看最近 100 条转换记录，完整计算快照保存在数据库。

## 管理员接口

- `GET /api/v1/admin/subscription-conversion`：读取开关。
- `PUT /api/v1/admin/subscription-conversion`：保存开关。
- `GET /api/v1/admin/subscription-conversion/users/:user_id`：查询目标用户预估和记录。
- `POST /api/v1/admin/subscription-conversion/users/:user_id/subscriptions/:id/convert`：
  提交转换，正文为 `{"quote":"预估返回的确认摘要"}`。

所有接口均要求管理员权限。后端同时校验订阅属于 URL 中的目标用户，
不接受客户端指定到账金额或操作人。普通用户无法通过直接请求这些接口发起转换。

## 本地验证

覆盖公式与精度、购买来源、越权访问、8 路并发重复提交、事务回滚、续费、
月额度变更、撤销后禁止恢复、历史迁移、计数重置和关闭开关的接口拦截。
另用隔离 PostgreSQL 验证历史 active、unsettled 租约不阻止转换，
并通过独立转换服务重复提交，确认不会再次增加余额。
后台任务测试覆盖余额预留在完成、放弃及异常时正确释放，
以及持久化计费在队列已满时仍同步执行。
前端覆盖开关、公式、不可转换原因、明确确认、提交失败和成功后刷新。
浏览器展示使用模拟数据；没有在正式环境执行真实订阅转换。
