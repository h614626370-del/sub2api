# 订阅转余额

管理员入口：**我的运维 → 订阅转余额**。默认关闭。开启后，用户侧出现同名菜单。
开关同时控制转换接口；关闭后即使保留旧页面也不能继续转换。

## 当前开发状态

当前实现已完成，尚未发布、部署或开启真实用户转换。
管理员配置、用户预估与确认、原子到账和撤销已通过定向检查。
用户确认采用即时判断：**该订阅仍有请求或扣费任务时拒绝转换；全部结算后重新提交即可**。
不排队、不自动等待，也不按晚到用量补扣转换余额。请求准入与转换共用订阅行锁，
避免“检查时没有请求、提交前又进入新请求”的竞争。HTTP 已返回但用量仍在后台排队，
仍视为有请求。视频生成的创建和状态查询跨请求：创建后保留待结算标记，
只有状态查询完成扣费才清除。取消、失败、创建结果不明或扣费失败时保守阻止转换，
需管理员核对；这些标记不按时间自动过期。上线前应先排空旧版在途请求，
因为迁移无法追溯升级前已经启动但尚未扣费的任务。

## 计算规则

```
转换余额 = 购买售价 × (剩余时间比例 × 50% + 剩余额度比例 × 50%)
剩余时间比例 = 剩余秒数 / 购买总秒数
总额度 = 月额度 × 购买天数 / 30
剩余额度比例 = max(总额度 - 订阅期间累计用量, 0) / 总额度
```

比例限定为 0–1；金额使用十进制定点计算，最终向下保留六位小数。
例如售价 30，剩余时间 50%、剩余额度 80%，到账 19.50。
仅支持月额度大于零、未配置日／周额度的分组。30 天为一个额度月；
续费累计购买天数，60 天按两个月额度计算。剩余时间精确到秒。

售价读取当前有效期内、已完成的支付订单 `amount`（购买时的套餐售价），
不读取套餐当前价格，不含支付手续费。沿用余额 USD 计价单位，不把上游网关
扣款金额 `pay_amount` 或展示币种标签当作另一份余额再换算。

## 来源与额度校验

- 管理员分配的订阅不允许自助转换。
- 交叉核验 `assigned_by`、支付订单备注、订单所有者、分组、支付发放审计与完成状态。
- 购买天数必须与当前有效期吻合。备注含赠送／兑换码、手动调整期限、订单缺失、
  退款或来源不明时展示不可转换原因，避免把无偿权益折算成余额。
- 同一订阅记录可能保留上一个到期周期的订单；仅当前周期的购买参与折算。
- 迁移 `269_subscription_conversions.sql` 从当前周期的订阅使用日志初始化累计用量。
  若检测到该周期内执行过日志清理，或日志汇总小于现有周期计数，则标记历史不完整，
  不开放转换。迁移前通过数据库外部操作删除的历史数据无法自动重建，应先核实数据完整性。
- 新增数据库计数由订阅用量更新触发；日／周／月窗口重置不清空累计值，
  到期后开始新的有效期才重置。之后清理使用日志不影响累计值。

## 确认与记录

用户查看有效订阅、预计到账、订单号与计算明细；勾选了解撤销和退款限制后提交。
服务器重新计算金额；时间流逝和新增已记账用量可能让到账低于预估。
若存在请求或待结算任务，页面说明原因，确认接口也会拒绝；结算完成后刷新再试。
期限、价格或月额度变化时，旧确认失效，必须刷新后重试。

余额增加、转换记录、余额变更记录、订阅撤销、订单状态与订单审计
在同一数据库事务内完成。用户与订阅行锁串行化重复提交，
转换记录以订阅 ID 为唯一键；重试返回原收据，不重复加款。
事务失败时全部回滚。提交后刷新订阅、余额及 API Key 认证缓存。

已转换订阅保留撤销记录，禁止恢复；关联订单标记为 `CONVERTED`（已转余额），
不能再退款或重新发放权益。原购买金额继续计入支付统计和每日支付限额。
转换本身不触发充值返利。用户显示最近 100 条转换记录，完整计算快照保存在数据库。

覆盖公式与精度、购买来源、越权访问、8 路并发重复提交、事务回滚、续费、
月额度变更、撤销后禁止恢复、历史迁移、计数重置和关闭开关的接口拦截。
另用隔离 PostgreSQL 验证请求准入与转换竞争、后台计费未结束、客户端断开、
跨请求视频扣费和失败结算保守阻断；后台任务测试覆盖实际提交与溢出同步兜底。
前端覆盖开关、公式、不可转换原因、明确确认、提交失败和成功后刷新。
浏览器展示使用模拟数据；没有在正式环境执行真实订阅转换。
